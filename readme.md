## Overview

_**This is a plugin for the [mdat CLI tool](https://github.com/kitschpatrol/mdat), which is a simple Markdown templating system optimized for embedding dynamic content in repository readmes and the like.**_

This plugin generates API documentation from a TypeScript library's public exports and embeds it in your Markdown file.

It uses [TypeDoc](https://typedoc.org) and [typedoc-plugin-markdown](https://typedoc-plugin-markdown.org) under the hood to extract JSDoc descriptions, type signatures, `@example` code blocks, and parameter tables directly from your source code, so the documentation in your readme can never drift from the implementation.

## Getting started

### Dependencies

We'll assume you have [mdat](https://github.com/kitschpatrol/mdat) installed either globally or in your local project.

### Installation

Install the plugin as a development dependency:

```bash
pnpm add -D mdat-plugin-api
```

Register the plugin in your mdat config file, e.g. `mdat.config.ts`:

```ts
import { defineConfig } from 'mdat'
import apiPlugin from 'mdat-plugin-api'

export default defineConfig({
  ...apiPlugin,
})
```

## Usage

Add an `<!-- api -->` placeholder comment to your Markdown file:

```markdown
## API

<!-- api -->
```

Then run the `mdat` CLI command on your Markdown file to expand the rule and embed the generated documentation. The [API](#api) section at the bottom of this readme is generated by the plugin itself, so you can see exactly what the output looks like.

### Options

Options are passed as a JSON5 argument in the placeholder comment:

```markdown
<!-- api({ entryPoint: "src/index.ts", headingLevel: 2 }) -->
```

See the `ApiRuleOptions` documentation in the [API](#api) section below for the available options.

### Entry point resolution

If no `entryPoint` option is provided, the plugin infers the TypeScript entry point from your project's `package.json`, checking in order:

1. `exports["."].types`
2. `exports["."].import`
3. `types`
4. `main`
5. Common defaults: `src/index.ts`, `src/lib/index.ts`, `index.ts`, `lib/index.ts`

Build output paths are mapped back to their sources, so a field pointing to `./dist/index.d.ts` or `./dist/index.js` resolves to `./src/index.ts`.

## API

<!-- api -->

### Function: setLogger()

> **setLogger**(`logger?`): `void`

Set the logger instance for the module. Export this for library consumers to
inject their own logger.

#### Parameters

| Parameter | Type                                  | Description                                                                |
| --------- | ------------------------------------- | -------------------------------------------------------------------------- |
| `logger?` | `ILogBasic` \| `ILogLayer`<`unknown`> | Accepts either a LogLayer instance or a Console- or Stream-like log target |

#### Returns

`void`

### Type Alias: ApiRuleOptions

> **ApiRuleOptions** = `object`

Options for the `<!-- api -->` rule.

Pass these as a JSON5 argument in the comment tag, e.g. `<!--
api({entryPoint: "src/index.ts", headingLevel: 2}) -->`.

#### Properties

| Property        | Type     | Default value | Description                                                                                                                                                                   |
| --------------- | -------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entryPoint?`   | `string` | `undefined`   | Path to the TypeScript entry point file. If omitted, the entry point is inferred from `package.json` fields (`exports`, `types`, `main`) or common defaults (`src/index.ts`). |
| `headingLevel?` | `number` | `3`           | Starting heading level for the generated documentation (1-6).                                                                                                                 |
| `tsconfig?`     | `string` | `undefined`   | Path to a custom `tsconfig.json` file. Auto-detected if omitted.                                                                                                              |

### Variable: default

> `const` **default**: `Config`

Mdat plugin that generates API documentation from TypeScript source files.

Uses TypeDoc and typedoc-plugin-markdown under the hood to extract JSDoc
descriptions, type signatures, `@example` code blocks, and parameter tables
from public exports.

Register in your `mdat.config.ts`, then embed `<!-- api -->` placeholder
comments in your Markdown files:

#### Example

```ts
import { defineConfig } from 'mdat'
import apiPlugin from 'mdat-plugin-api'

export default defineConfig({
  ...apiPlugin,
})
```
